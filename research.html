Current research

Cost-Optimal Model Selection and Adaptive Agent Coordination

Status: Research proposal · Evaluation planned

My proposed research asks a practical question: what is the lowest-cost combination of models and agents that can reliably complete a task? I plan to study an adaptive orchestration layer that combines self-hosted open-source models with external model APIs, choosing where to spend compute, when to escalate, and how much context each agent actually needs.

The objective is to approach the best model choice for each task under explicit quality, latency, and budget constraints. The system would learn from measured outcomes rather than assume that the largest model is always the strongest choice.

  • Learning which model to use: Investigate contextual bandit routing using task embeddings, difficulty estimates, prior outcomes, and inference costs. Compare the learned policy against fixed routing and the best model chosen in hindsight.
  • Small-model-first execution: Explore cascades that start with inexpensive open-source models and escalate only when task checks or calibrated uncertainty indicate that more capable reasoning is needed. Study when verification costs more than the savings it enables.
  • Budget-aware agent planning: Represent a task as a graph of dependent subtasks and allocate models, token budgets, and parallel work to each stage. Account for retries, verification, and communication overhead in the total cost of completing the task.
  • Selective context and reusable memory: Test retrieval-based handoffs, compressed working memory, and semantic caching so agents receive relevant evidence without replaying the entire history. Measure whether compression or cache reuse loses details needed for correct answers.
  • Open-source inference experiments: Plan a reproducible testbed for comparing quantized models, batching, and prefix caching. Include GPU time, utilization, and hosting overhead so self-hosted inference is evaluated on its actual operating cost.
  • Adaptive stopping and recovery: Investigate when another agent or model call is worth its expected improvement, when the system should stop, and how it should recover from an incorrect intermediate result without restarting the full workflow.

Planned evaluation

Evaluate coding, retrieval, and multi-step reasoning workloads against a single strong model, a single low-cost model, fixed cascades, and static multi-agent workflows. Report task success, cost per successful task, token usage, tail latency, and routing regret relative to the best model in hindsight. Ablation studies would isolate the effects of routing, memory compression, caching, and verification.

The target outcome is a reproducible quality–cost frontier showing where adaptive orchestration saves resources and where the additional coordination fails to pay off. Results will be added as experiments are completed.

Ongoing project

Task-Aware Multi-Model Agent Orchestration

Status: In development

I’m developing an orchestration system that selects a suitable language model for each task and coordinates agents across different model providers, including OpenAI. The goal is to use each model where it performs best while reducing unnecessary token usage and context overhead.

  • Task-based model selection: Route work to models according to the task’s requirements, balancing response quality, cost, and latency.
  • Cross-provider agent communication: Let agents powered by different models exchange intermediate results and coordinate within a shared workflow.
  • Context-efficient handoffs: Pass relevant information between agents rather than repeatedly sending the entire conversation history.
  • Evaluation goals: Compare the orchestration approach with single-model workflows on task quality, token consumption, latency, and cost.
